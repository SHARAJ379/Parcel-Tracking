Authentication

Send the API key in the x-api-key header. Read keys can retrieve parcels and use the assistant. Write keys can create parcels, update status, and manage webhooks. Never put a key in browser code or a public repository.

curl -H "x-api-key: YOUR_API_KEY" \
  https://your-app.example/api/v1/parcels/DEMO-PARCEL-001

Create a parcel POST · 201

Creates a parcel and its initial timeline event.

curl -X POST https://your-app.example/api/v1/parcels \
  -H "x-api-key: YOUR_WRITE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"tracking_id":"DEMO-NEW-001","destination":"London","eta":"2026-12-01T10:00:00Z"}'

Get tracking details GET · 200

Returns an owner-scoped parcel and its timeline in chronological order. The ID may be the tracking ID, a courier AWB number or a shop order ID. An order ID with several shipments returns 409 ambiguous_order_id listing their tracking IDs.

curl https://your-app.example/api/v1/parcels/DEMO-PARCEL-001 \
  -H "x-api-key: YOUR_READ_KEY"

Update parcel status PATCH · 200

Updates status and appends a timeline event. Valid statuses: created, picked_up, in_transit, out_for_delivery, delivered, delayed, failed_delivery.

curl -X PATCH https://your-app.example/api/v1/parcels/DEMO-PARCEL-001/status \
  -H "x-api-key: YOUR_WRITE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"status":"in_transit","location":"Sorting facility"}'

Parcel assistant POST · 200

Answers questions in English, Hindi or Kannada using only your parcel’s records, and declines unrelated requests. The tracking ID can be sent in tracking_id or written inside question. For follow-up questions, send up to 10 earlier turns in history (oldest first, roles user or assistant). Each text is limited to 1,000 characters. The assistant is read-only.

curl -X POST https://your-app.example/api/v1/assistant \
  -H "x-api-key: YOUR_READ_KEY" \
  -H "Content-Type: application/json" \
  -d '{"question":"And when will it arrive?",
       "history":[{"role":"user","text":"Where is DEMO-PARCEL-001?"},
                  {"role":"assistant","text":"It is in transit at the sorting facility."}]}'

The response contains the answer and the records it was based on. tracking_id and parcel are null when no tracking ID was given; an unknown ID returns 404.

{"success":true,"data":{
  "answer":"It is expected on 01 Dec 2026, 03:30 PM IST.",
  "tracking_id":"DEMO-PARCEL-001",
  "parcel":{"id":"…","tracking_id":"DEMO-PARCEL-001","status":"in_transit","eta":"2026-12-01T10:00:00+00:00", …},
  "timeline":[{"status":"in_transit","location":"Sorting facility","occurred_at":"…","description":"…"}]}}

Webhooks

Register HTTPS endpoints, list the owner’s endpoints, or delete an endpoint by ID. The registration response includes its signing secret once.

curl -X POST https://your-app.example/api/v1/webhooks \
  -H "x-api-key: YOUR_WRITE_KEY" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://example.com/webhooks/parcels"}'

curl https://your-app.example/api/v1/webhooks \
  -H "x-api-key: YOUR_READ_KEY"

curl -X DELETE https://your-app.example/api/v1/webhooks/WEBHOOK_UUID \
  -H "x-api-key: YOUR_WRITE_KEY"

Verify delivery signatures

Compute HMAC-SHA256 over the exact UTF-8 request body using the webhook secret. Compare it with X-Signature: sha256=<lowercase-hex-digest>. Do not parse and re-serialize the body first.

Inbound email POST · 200

CloudMailin posts forwarded parcel emails here in its JSON (Normalized) format. This route uses Authorization: Bearer <INBOUND_EMAIL_SECRET> instead of an API key, and only senders in ALLOWED_EMAIL_SENDERS are accepted. Gemini extracts the shipments; only values written in the email are stored.

curl -X POST https://your-app.example/api/v1/inbound-email   -H "Authorization: Bearer YOUR_INBOUND_SECRET"   -H "Content-Type: application/json"   -d '{"envelope":{"from":"you@example.com","spf":{"result":"pass"}},"headers":{"message_id":"<test-1@example.com>"},"plain":"Waybill No. 81234567890 is out for delivery to MYSURU. Blue Dart"}'

200 returns result: imported, updated, unchanged, no_shipment, failed or duplicate. 401 wrong secret, 403 sender not allowed or SPF failed, 413 over 1 MB, 429 rate limited, 503 Gemini unavailable (CloudMailin retries).

Responses and errors

{"success":true,"data":{"tracking_id":"DEMO-PARCEL-001"}}
{"success":false,"error":{"code":"parcel_not_found","message":"No parcel matches that tracking ID."}}
  • 400 Invalid input or webhook URL
  • 401 Missing or invalid API key
  • 403 API key lacks the required scope
  • 404 Parcel or webhook not found
  • 409 Tracking ID already exists
  • 429 Rate limit or assistant quota reached
  • 502 / 504 Assistant upstream error or timeout
